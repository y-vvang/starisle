# 星屿 Starisle · 后端演示(读这页,会前 2 分钟够了)

## 这是什么

`demo/backend-demo.sh` 是一段可重复运行的脚本,直接对着重写后的 PostgreSQL
后端打真实 API 请求(不经过浏览器),从一个空数据库开始,讲完"建站长 → 新人
申请 → 审核 → 发项目 → 审核 → 重启进程数据还在"这一整条链路。88 个单测已经
绿了(跑 `npm test` 自己核对这个数字,别直接抄这里的——它会随后续任务变),
这个脚本是给人看的、只打 API 不碰浏览器的版本。

**这份文档写的时候前端还没跟上,现在已经跟上了。** Vue 前端后来被整体重建
(主站 3 页 + 控制台 4 页,见仓库根目录 `README.md`),接的是这份重写后的真实
账号 API,不再是旧的内存版接口。这份 `demo/backend-demo.sh` 依然有用——它是
**只打 API、不经过浏览器**的最短验证路径,适合快速核对后端行为或没有浏览器
的场合,但它不再是"前端还没做完所以只能这样演示"的替代品;要看完整的网页体验,
按 `README.md` 的"快速开始"跑起来,打开 `http://localhost:4870/`。

## 怎么跑

```bash
bash demo/backend-demo.sh
```

在 Git Bash 里执行。大概 15-20 秒跑完全部 14 步。跑完自动清理(关掉自己起的
服务进程),可以反复跑,每次都从空数据库重新开始,不依赖上一次的残留状态。
用的是独立数据库 `starisle_demo` 和独立端口 `4920`,不碰 `starisle` /
`starisle_test*`,也不会动到你本地其它正在跑的服务。

前提:Postgres 容器 `starisle-db` 在跑,`docker exec` 能连上。

## 会上要指给大家看的三个点

脚本里这三步专门做了醒目标记(带 `>>>` 或 `★★★`),投屏时直接找这几行:

1. **审核门是真的**(步骤 3):新人注册完立刻登录,服务端返回 `403` +
   "申请审核中"。这不是前端隐藏了按钮,是后端真的拒绝。步骤 4 再补一刀:
   匿名查成员列表,这个新人压根不出现。

2. **项目绑定到发起人本人**(步骤 12):项目审核通过后,匿名查询
   `/api/projects` 拿到的 `owner` 字段是新人 `xiaoyu`,不是站长
   `zhanzhang`。这证明"谁发起的算谁的"这条业务规则落到了数据库外键上,
   不是界面上写了个名字。

3. **重启进程,数据没丢**(步骤 14,全场最重要的一步):脚本会真的把
   Node 进程杀掉、另起一个全新进程,再查一遍项目列表 —— 项目和它的
   owner 原样还在。旧的内存版demo每次重启/重新部署都会把所有账号和项目
   清空回出厂状态;这是这次重写要解决的核心问题,这一步就是证据。

顺带在步骤 13 也证明了一件事:匿名请求后台待审用户接口(里面有申请人
邮箱等 PII)直接 `401`,不登录站长身份读不到 —— 这是上一版安全止血
(P0 鉴权)的效果,这次没有跟着重写走样。

## 如果脚本失败了

脚本对每一步都有断言,哪一步的响应不符合预期就会立刻停在那一步,打印
"失败: 步骤 N ——原因",退出码非零。这种情况**不要**弱化断言让它"看起来
过了" —— 那一步失败说明后端行为跟预期不一致,是需要真的去看一眼的信号,
不是脚本的问题。
